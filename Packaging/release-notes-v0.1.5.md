Media Memory v0.1.5 makes pictures first-class citizens, reworks processing into a library-level queue, and opens the library to AI agents. Images are now scanned, thumbnailed, embedded, described and searchable alongside videos (animated images are deliberately not supported; the library records pixel dimensions and kind per asset, schema v10). Processing moves from per-root scanning to a library-level queue: videos are processed strictly one at a time while frames, audio and embeddings inside a video run in parallel lanes; the order is stored in the database (schema v11) so "process this root next" survives restarts and reorders by writing a single row. The sidebar regroups roots into 处理队列 and 已完成, and the bottom status panel is rebuilt around a constant per-media denominator with a three-stage funnel (segments → index → descriptions) and a live activity line with 5-second receipts instead of a pseudo log. A new zero-dependency MCP server (media-memory-mcp, bundled inside the app) exposes read-only semantic retrieval over the stdio protocol, and a new Agent Integration panel registers it into Claude Code, Codex or ZCode in one click. Model credentials migrate from the Keychain to a user-only credentials file (0600), removing the per-update Keychain permission prompts inherent to self-signed apps without a Team ID. The library gains a case-insensitive relative-path filter, and the app ships a new hand-felted polaroid icon with matching brand marks in the empty state, settings and agent panels. Test suite grows from 133 to 207 tests.

Upgrade notes from v0.1.4:

- First launch migrates the database in place from schema v9 to v10 (image support) and v11 (processing order). All indexed data, vectors, descriptions and credentials are preserved; a backup of the previous database file is kept next to the original.
- Model credentials are migrated out of the Keychain into `model-credentials.json` in the app support directory (permissions 0600, user-readable only). The migration runs once on first launch; if a stored key cannot be read, re-enter it in 模型设置. Self-signed builds no longer trigger repeated Keychain access prompts across app updates.
- The MCP server binary (media-memory-mcp) lives inside the app bundle next to the main executable. It speaks the stdio protocol in both the current and legacy revision, registers strictly as a read-only retrieval service, and gates on schema version — pointing an agent at an old library version fails with an explicit message instead of returning partial results.
- Animated images (GIF and similar) are not supported: they are reported in the scan summary and excluded from indexing rather than silently misindexed.

The App remains self-signed and is not Apple-notarized. The signing private key and encrypted backup are not included in the repository, DMG, or Release assets.
