# Media Memory 第一版产品与技术方案

- 状态：已确认，作为第一版实现的单一方案来源
- 文档修订：0.6（不同于应用版本）
- 日期：2026-08-25（本次修订内容感知分片与无空窗代际迁移，见 D-016）
- 目标平台：仅 macOS / Apple Silicon
- 实现状态：单机可用版 V0 功能第一版已实现并通过单个真实视频闭环；代表性视频库规模验收与持续使用仍待完成

## 1. 决策摘要

Media Memory 是一个本地优先的个人影像记忆工作台：默认把本地视频稳定地变成可验证、可定位、可检索的时间片段。模型服务默认为本机回环地址，也可由用户显式改成远程 HTTP(S) 端点；第一版要完成的不是“自动剪片”。

系统只保留一条生产链路：

```text
本地视频
  ↓
只读扫描与统一时间轴 → 画面变化 + 静音停顿 → 变长内容片段
  ↓
每个内容片段
  ├─ 音频 → Qwen3-ASR → Qwen3-ForcedAligner → 按句聚合的带时间戳转写
  └─ 低频候选帧 → 去重后的代表帧 → Apple Vision OCR → 带时间戳的画面文字
  ↓
关键帧 + ASR + OCR
  ↓
Qwen3-VL-Embedding-2B → 每个片段一个融合向量 → 唯一语义索引（提交后即可搜索）
  ↓
输入一句话 → 返回原文件、命中时间和证据 → 点击播放
  ↓
证据车道提交后 → 描述车道自动逐段调用 Qwen3.8 → 描述缓存 + 增量画面召回
```

内容分片生产者、证据车道（ASR/对齐/OCR/Embedding，小模型串行）与描述车道
（Qwen3.8）组成流水线：生产者按视频稳定排序，只读生成片段；每个视频一旦完成
分片即可由证据车道消费，不等待其他视频；描述车道并行消费已提交证据。证据车道
在模型计算时预读下一个片段的音频与帧，使网络读取与 Metal 计算重叠。

以下约束已经锁定：

1. 默认回环配置不把数据发出本机；若用户改成远程 HTTP(S) 模型端点，片段音频、代表帧和文字证据会发送到该端点，非本机服务必须优先使用 HTTPS。
2. 原素材只读；产品不移动、改名或删除源文件。
3. 每项职责只有一个生产实现，不内置主模型/备用模型双轨。
4. 候选只能在实现前做一次性验收；失败就替换并移除，不作为 fallback 留在系统里。
5. 全库检索不依赖生成式描述；描述遗漏的细节不能成为检索盲区。
6. 只有一个语义向量索引。FTS 索引 ASR/OCR 原文和描述中的可观察画面内容，用于可解释的字面召回，不是第二套语义系统。
7. 多个重模型可以驻留，但不同时抢占 Metal 做满负载推理。

## 2. 产品目标与边界

### 2.1 第一版必须做到

1. 用户选择一个或多个本地媒体目录。
2. 系统只读扫描视频，识别新增、变化、移动和不可读取的文件。
3. 后台生成可审计的 ASR、时间戳、OCR 和片段向量。
4. 用户既可以按原话搜索，也可以按语义搜索，例如：
   - “我们在京都车站讨论晚饭的片段”；
   - “海边日落时有人举杯”；
   - “画面里出现 welcome 标牌”。
5. 每个结果返回原文件、`start_ms`、`end_ms`、命中证据和上下文。
6. 点击结果后直接从原文件对应时间播放。
7. 用户打开结果时可以直接看到建库后自动生成的片段描述（基于画面、声音文本和 OCR）。
8. 索引任务可暂停、恢复；应用重启后不重复处理未变化文件。

“输入一句话立即找回”指素材完成预处理后的热检索体验，不承诺未建库素材可以即时搜索。

### 2.2 个人可用版 V0 的完成定义

1. 可以选择本地媒体目录，且处理过程不修改源文件。
2. 可以稳定建库、暂停、恢复，重启后不会重复处理未变化文件。
3. 一句话查询同时支持 ASR/OCR 字面检索与跨模态语义检索。
4. 每个结果展示命中证据，而不只给出模型结论。
5. 点击结果可以按句段或片段时间准确跳回原视频。
6. 建库进度、当前阶段和失败原因可见，失败任务可以重试。
7. 在代表性真实视频库中持续使用稳定，再判断 V0 完成。

### 2.3 当前阶段不做

- 内置云端账号、托管模型或云端索引；
- 自动剪辑、自动成片和发布；
- 人脸识别、身份推断和人物关系判断；
- 无证据的情绪、动机或事件推断；
- 同时维护两套 ASR、Embedding、描述模型或向量索引；
- 为追求“全模态”而引入不能满足时间戳或检索要求的大一统模型；
- Windows、Linux、iOS 或团队协作。

### 2.4 个人版稳定后再评估

以下方向保留为未来可能性，但不作为当前架构和验收的负担，也不提前建设通用抽象：

- Developer ID 签名、Apple 公证、App Store 和自动更新；
- 应用内的模型服务发现、模型下载与自动配置；
- 应用内模型下载、Python 运行时打包和多硬件适配；
- 插件系统和第三方扩展。

## 3. 核心原则

### 3.1 原素材只读

扫描、解码、识别、索引和播放均不得修改源文件。应用生成的数据统一写入独立数据目录，包括：

- 文件事实与指纹；
- 任务和错误状态；
- ASR、时间戳和 OCR；
- 关键帧缓存；
- 向量索引；
- 自动片段描述。

源目录中的符号链接不得被递归跟随到用户未选择的目录。

### 3.2 统一使用源媒体时间轴

所有结果必须基于 AVFoundation 返回的 `CMTime` / 实际 PTS。不能仅使用“样本数 ÷ 采样率”或“帧序号 ÷ FPS”推算绝对时间，因为 edit list、可变帧率、轨道偏移和间隙会造成漂移。

最小可定位证据为：

```text
asset_id + start_ms + end_ms + evidence_type + derivation_run_id
```

### 3.3 事实与派生结果分离

- 文件路径、大小、容器时长、轨道和 PTS 属于观测事实。
- 转写、语言、句级时间戳、OCR、向量和描述属于派生结果。
- 每条派生结果记录模型 ID、运行时版本、参数和源文件指纹；数据库已预留模型 SHA 字段，正式制品锁定 revision 后再填入，当前不得伪造。
- 派生数据可以失效和重建；源素材永远是最终证据。

### 3.4 一个职责，一个实现

“单链路”不是只允许一个 checkpoint，而是每项职责只有一个固定实现。ASR、强制对齐、OCR、Embedding 和描述产生的输出不同，彼此不是备用关系。

系统不得出现：

- ASR 失败自动切换备用模型；
- Embedding 同时写入 2B 和 8B 两套索引；
- Qwen3.8 失败自动切换另一 VLM；
- 长期保留旧模型索引作为备用查询路径。

升级模型时，只允许在临时派生区完成重建并原子切换；切换成功后删除旧派生版本。

## 4. macOS 应用结构

第一版采用原生 macOS 应用、按能力区分的 HTTP 接口，以及一个可选的本地 MLX 工作进程：

```text
SwiftUI macOS App
  ├─ 目录授权与只读扫描
  ├─ AVFoundation 解码、抽帧和播放
  ├─ Apple Vision OCR
  ├─ SQLite 数据与任务状态
  ├─ 搜索、结果展示和时间跳转
  └─ 单一模型调度器
        ├─ OpenAI 兼容 HTTP
        │   ├─ audio/transcriptions → ASR
        │   └─ multimodal chat/completions → 片段描述
        ├─ Media Memory HTTP 契约
        │   ├─ alignment → 强制对齐
        │   └─ multimodal embedding → 片段与查询向量
        └─ 可选本机进程通信 → Python / MLX Worker
            ├─ 强制对齐
            └─ 多模态向量
```

边界如下：

- Swift 负责 macOS 系统能力、文件权限、媒体时间轴、OCR、数据库和 UI。
- 每项能力分别保存完整请求 URL、模型名称和 API key；服务可以位于本机、局域网或远程，不以供应商名称判断能力。
- ForcedAligner 需要“音频 + 已知转写”并返回时间项；Embedding 需要把多帧与文本融合成一个向量。二者没有可依赖的通用行业接口，因此使用项目公开的最小 HTTP 契约，或选择内置 Worker。
- Python/MLX Worker 只接收已经限定范围的本地音频或帧任务，返回结构化派生结果。
- 模型工作进程不扫描用户目录，不拥有任意路径读取接口。
- 第一版不引入 Redis、Celery、PostgreSQL、内置云服务或服务发现层。
- 配置与派生记录包含传输协议、完整 URL 和模型 ID 的稳定摘要；切换服务或模型会使相应派生结果失效并重建，API key 不进入摘要或配置文件。
- 默认配置只通过回环地址发送音频、图片和文字。设置页允许替换为其他 HTTP(S) 地址；用户必须确认服务可信，远程服务应使用 HTTPS。
- 设置页的四项“测试”都执行真实最小请求，但只使用应用生成的音频、图片与文字，不读取媒体库。

### 4.1 UI 与后台任务边界

界面层只负责发布状态和接收用户命令，不执行可能阻塞的文件、数据库、媒体或模型工作：

- 启动分成“本地核心加载”和“后台维护”两段。配置、数据库打开与迁移在非主线程完成；界面就绪后，孤儿文件清理、书签续期、钥匙串读取和模型服务创建各自异步继续。
- 安全书签、钥匙串、配置写入、目录属性读取、缓存清理和播放器资产准备都有显式异步边界；SwiftUI 主线程不做同步 I/O。
- App 只读操作、扫描、媒体库控制命令、搜索、播放器以及两条模型车道分别拥有受管任务和状态；搜索或扫描不得暂停、恢复、重置或取消后台车道，后台事件发布也不反向等待界面消费。App 快照、搜索各使用自己的 SQLite/WAL 只读连接，扫描、控制命令和后台提交使用第三条写连接。媒体库、任务仪表盘和全文结果各自在一个读事务中组装；语义结果若检测到组装期间数据库版本变化会重试，持续变化时降级为一致的全文快照。
- 会修改媒体库的控制命令自身串行执行，但不取消扫描或模型任务。数据库任务通过 `job id + attempt_count` 认领令牌提交，删除、重排或新尝试发生后，旧尝试即使较晚返回也不能写入、失败或改回队列。
- MLX Worker 使用异步管道读取，不在 Swift actor 上同步等待子进程。前台查询取消只丢弃该查询结果，不终止共享 Worker；超时或后台原子操作取消仍按故障边界终止并重建 Worker。HTTP 的 ASR 和描述请求分别有 5 分钟、10 分钟上限。
- AVFoundation 音频读取、抽帧和播放器加载响应任务取消；详情页一次批量读取全部片段描述，缩略图使用有界串行解码与缓存，避免滚动时创建无上限后台任务。

这里的“解耦”指生命周期、任务状态和提交所有权互不传播；共享数据库或模型资源仍可在资源层排队，但排队不得转化为另一条业务链路的取消、重置或失败。

### 5.2 ASR 与时间戳边界

Qwen3-ASR 支持语言识别和 30 种语言、22 种中文方言的转写。Qwen3-ForcedAligner 的精确词/字级对齐仅覆盖：

```text
中文、粤语、英语、法语、德语、意大利语、日语、韩语、
葡萄牙语、俄语、西班牙语
```

ForcedAligner 仍会在内部产生词/字对齐项，但第一版产品只保存和展示“一句话从什么时候开始、什么时候结束”，不保存逐字时间。句子边界由 ASR 标点确定，再把内部对齐项聚合为句级范围。

因此第一版的明确保证是：

- 上述 11 种语言：由词/字对齐结果聚合出的句级时间范围；
- 其他 ASR 支持语言：ASR 句段或处理块时间范围，不承诺同等精度的句首句尾。

长音频必须先切块。单个 ForcedAligner 输入不得超过官方 5 分钟限制；第一版采用不超过 180 秒的音频块，并保留源时间偏移。边界合并必须去掉重复词，不能让局部时间覆盖全局时间。

### 5.3 OCR 不由 VLM 兼任

VLM 能理解画面文字，但不能替代可展示、可字面搜索、带位置和置信度的 OCR 证据。Apple Vision 只处理抽样帧，不逐帧扫描整段视频。

相邻帧的相同字幕或招牌必须先按文本、位置和时间去重，再写入证据表。OCR 结果的时间来自实际抽帧时间，而不是帧序号估算。

### 5.4 Embedding 直接索引原始证据，描述只补充 FTS

每个片段只生成一个融合向量，输入为：

```text
有序关键帧 + 帧时间提示 + 片段 ASR + 去重 OCR
```

第一版使用 2B 而不是 8B：官方基准中 8B 的视频检索更强，但约有 4 倍参数量、更高索引成本和更慢的全库处理。对于大量长视频，2B 是质量、吞吐和内存的系统最优点。

在一次性验收中可以比较 2B 与 8B；如果 8B 在自有困难查询上的收益明确超过成本，就整体替换 2B。生产环境永远只保留一个模型和一个索引。

第一版不依赖 MLX 的原生视频 Embedding 输入。Mac 上相关处理链仍较新，生产路径使用共享的有序关键帧和文本混合输入，避免引入第二套视频处理器。关键帧仍保留顺序和时间信息。

### 5.5 Qwen3.8 负责导入后的批量描述

Qwen3.8-27B 是当前选定的视觉语言生成模型，它在建库流程中由独立的描述车道运行：

- 每个片段的证据与向量提交后，自动进入描述队列，逐段生成描述并缓存；
- 描述车道与证据车道并行，但不阻塞检索：片段在向量提交后即可被搜索；
- 输入复用 Embedding/OCR 已抽取的有序关键帧，并加入 ASR、OCR 和时间范围；
- 输出结构化描述并缓存；描述契约只覆盖模型能实际观察的内容（画面摘要、画面细节、不确定项）——模型没有音频输入，语音的权威来源是 ASR 证据，画面文字的权威来源是 OCR 证据，描述不重复、不冒充它们；
- 描述不回灌向量；`summary` 与 `visible_details` 作为标明来源的画面描述补充 FTS，`uncertainty` 不进入正向召回；
- 描述任务失败标记为可重试任务，不影响该片段的可搜索性；
- 数据性失效自动重跑（新片段补描述、证据重提交后旧描述作废）；prompt 或描述模型变更属于配置性失效：不自动重跑，界面标记“旧版生成”并提供片段级、视频级、全库级手动重跑入口。

当前目标 Mac 已完成 oMLX 多帧加文本的基础调用验证，证明模型能够加载并生成片段描述。该结果只解除“能否调用”的阻塞，不等于完成生产验收；多图顺序、事实准确率、长时间稳定性和峰值内存仍按第 12 节验收。

### 5.6 为什么不使用一个全模态模型

全模态生成模型可以同时理解音频和视频，但不能消除以下必要输出：

1. 可审计、可回到源时间轴的句级时间戳；
2. 带位置和置信度的 OCR 证据；
3. 经过检索训练、可做近邻搜索的稳定向量。

生成模型和 Embedding 模型的训练目标不同。直接池化 Qwen3.8 隐藏层没有经过检索对比学习；Qwen3-VL-Embedding 则移除了生成头并针对跨模态检索训练。让一个 checkpoint 同时承担生成与检索会降低可验证性，不是更简洁的方案。

Qwen3-Omni 和 Gemma 4 等模型也没有同时提供强制对齐与检索向量，因此不进入第一版生产链。

## 6. 时间片段与抽帧策略

### 6.1 内容感知的变长片段

生产分片使用两类独立的源时间轴观察：低频画面样本之间的视觉变化，以及 PCM
固定能量窗检测到的静音结束。规划器把邻近信号合并后确定边界：最短 4 秒，优先
8–15 秒，30 秒硬上限；快剪会聚合，长镜头在没有可信边界时才使用确定性兜底。
输出始终连续、无重叠并完整覆盖源时间轴：

```text
segment_id
asset_id
start_ms
end_ms
```

所有 ASR、OCR、向量、描述和 UI 结果都挂在同一个 `segment_id` 上。画面边界样本
只用于分片判断，不等于后续持久化的代表帧。旧版 20 秒片段只作为迁移期间的活动
代际保留；新代际全部完成向量后一次性切换。上一代画面描述在新代际描述补齐前
继续参与字面检索，避免切换后出现描述召回空窗。数据库最多保留当前与上一活动
代际；从未活动的 staged 代际被新算法取代时直接删除。

### 6.2 共享帧采样

每个片段使用同一套候选帧，避免 OCR、Embedding 和描述分别解码视频：

1. 按源时间轴低频抽取候选帧，初始值为 1 fps；
2. 记录 AVFoundation 返回的实际时间；
3. 对近重复帧和连续字幕帧去重；
4. OCR 可以处理全部保留候选帧；
5. Embedding 和描述从中选择最多 8 张代表帧，并保留时间顺序。

不把整段视频复制为代理文件，不逐帧运行 OCR，也不为每个模型建立独立帧缓存。

## 7. 数据模型

SQLite 是事实和任务状态的单一来源。向量索引是可重建派生物。

### `library_root`

- 用户授权的根目录和安全作用域书签；
- 是否启用、最近扫描时间；
- 扫描不得越过授权边界。

### `media_asset`

- 规范化路径、文件标识；
- 大小、修改时间、容器时长、轨道信息；
- 轻量指纹和当前状态；
- 首次发现、最近发现和失效时间；
- 排除标记：用户移除单个视频后行保留为标记，扫描不再纳入，派生数据全部删除。

### `segment`

- `asset_id`；
- `start_ms`、`end_ms`；
- 片段代际、对应分片运行与是否为当前活动代际。

### `timeline_boundary_observation`

- 画面变化或静音结束在源视频中的实际 `time_ms`；
- 归一化分数和可审计参数（前一画面样本时间、静音起点与时长）；
- 对应分片 `derivation_run_id`，不与代表帧混为一类数据。

### `derivation_run`

- 类型：`segmentation`、`asr`、`alignment`、`ocr`、`embedding`、`description`；
- 模型 ID、运行时版本和参数；`model_sha` 字段当前为空，等待制品 revision 正式锁定；
- 源文件指纹；
- 状态、开始/完成时间和错误摘要。

### `transcript_segment`

- 原始转写文本和语言；
- 句子 `start_ms`、`end_ms`；
- 时间来源：内部强制对齐聚合或 ASR 处理块范围；
- 对应 `derivation_run_id`。

第一版不建立逐字时间表。ForcedAligner 的词/字级输出只存在于当前任务内，用于计算句子边界后即释放。

### `ocr_observation`

- 文本、置信度和标准化框；
- 帧时间和合并后的可见时间范围；
- 对应 `derivation_run_id`。

### `segment_frame`

- 代表帧在源视频中的实际 `time_ms`；
- 应用工作目录内的相对路径和感知哈希；
- Embedding 与自动片段描述复用同一组有序帧。

### `segment_embedding`

- `segment_id`；
- 向量维度和索引键；
- 模型与输入派生版本；
- 每个有效片段只允许一个当前向量。

### `segment_description`

- `segment_id`；
- 结构化描述；
- `input_version` 覆盖素材指纹、代表帧、ASR/OCR 证据、模型 ID 和 prompt 版本；模型 SHA 尚未纳入；
- 仅作为可删除缓存。

### `job`

- 扫描、探测、抽帧、ASR、对齐、OCR、Embedding、描述等类型；
- `pending/running/succeeded/failed/cancelled`；
- 尝试次数、检查点和错误摘要。

## 8. 索引流水线

1. **扫描**：只读取用户授权目录，识别支持的媒体文件并拒绝越界符号链接。
2. **稳定性检查**：文件大小和修改时间在两次观察之间不再变化后才排队，避免处理仍在复制的素材。
3. **媒体探测**：由 AVFoundation 读取时长、轨道、时间范围和可播放状态。
4. **时间轴预分析**：低频取图按最多 7,200 个样本自适应调大间隔，每批最多 240 个请求，只跨批保留上一张缩略图，并按实际 PTS 排序去重；音频按实际采样率、跨缓冲固定能量窗检测静音，二者都只读源文件。
5. **内容分片**：确定性合并边界候选，写入新的非活动片段代际和可审计时间轴观察。
6. **音频读取**：逐片段流式读取并转换为模型需要的 16 kHz 单声道 PCM，不复制完整视频。
7. **ASR**：Qwen3-ASR 输出语言和文本，所有局部时间换算回源媒体时间轴。
8. **强制对齐**：支持的 11 种语言先产生临时词/字对齐项，再按 ASR 标点聚合为句级范围；其他语言保留 ASR 句段或处理块范围。
9. **共享抽帧**：生成带实际时间的低频候选帧并去重。
10. **OCR**：Apple Vision 输出文字、框、置信度和可见时间，合并重复结果。
11. **Embedding**：每个片段把代表帧、ASR 和 OCR 一次编码为一个向量。
12. **原子切换**：新代际全部片段均有向量后，一次事务切换活动代际；旧搜索结果在此之前保持可用，旧画面描述继续兜底到新描述全部存在。
13. **描述**：证据提交后独立车道生成描述，不阻塞片段进入搜索。
14. **清理**：清除临时音频和中间帧；代际切换后在同一进程回收已无数据库引用的代表帧，只保留当前与上一活动代际；绝不触碰源视频。

任何阶段失败都写入明确状态并停止该素材后续依赖任务，不自动切换另一模型。

## 9. 搜索与播放

### 9.1 字面证据检索

SQLite FTS 索引 ASR、OCR 原文和 Qwen 描述中的可观察画面内容，解决：

- 用户记得完整原句；
- 人名、地名、编号和招牌文字；
- 需要展示精确命中文本的查询。

描述只补充召回：`summary` 与 `visible_details` 标为画面来源，`uncertainty` 排除；已有描述在数据库升级时原地补索引，新描述在提交事务中同步更新。用户输入必须参数化传给 SQLite，不拼接 SQL 或 FTS 表达式。

### 9.2 语义检索

1. 使用同一个 Qwen3-VL-Embedding-2B 对查询文本生成向量；
2. 从 SQLite 读取当前模型与输入版本的唯一向量集合，并在内存中按版本缓存；
3. 使用 Accelerate 对归一化向量做精确余弦排序；
4. 字面候选按 BM25 名次归一化，语义候选使用正余弦相似度，按 `65% 字面 + 35% 语义` 融合；缺失语义不扣分，非正相似度不召回；
5. 先按片段计算综合分，再按 `asset_id` 聚合；每个视频只返回最高分片段作为证据与播放落点，其余候选片段只贡献视频级来源命中统计，避免长视频在列表中重复占位；
6. 卡片展示最高分片段的字面分、语义相似度、BM25 和综合分，并汇总整个视频的视频描述命中片段数、OCR/ASR 命中条数；画面、语音、文字可同时出现，同来源只展示最相关的一条；
7. 不增加生成式 reranker。

个人版当前不引入 HNSW 等 ANN 结构。精确排序召回不打折，也省去第二份持久索引及其增量一致性问题；仓库提供 10,000 个 2048 维向量的显式性能测试，只有目标硬件证明这一实现无法满足热查询 `p95 < 1s` 时，才整体替换唯一向量索引，而不是并存两套。

### 9.3 播放

使用 `AVPlayer` 打开数据库中已授权的源文件，并跳转到 `start_ms`。播放接口只接受 `asset_id` / `segment_id`，不接受任意文件路径。

## 10. 资源预算与调度

### 10.1 已验证硬件边界

选定格式的静态权重约为：

| 模型组 | 约占用 |
|---|---:|
| Qwen3-ASR 1.7B 8-bit | 2.41 GB |
| Qwen3-ForcedAligner 0.6B BF16 | 1.79 GB |
| Qwen3-VL-Embedding-2B BF16 | 4.16 GB |
| Qwen3.8-27B 4-bit | 15.70 GB |
| 合计 | 24.06 GB |

在 64 GiB 级别的参考环境中，这些权重可以共存；运行时、KV cache、视觉张量、帧缓冲和 macOS 仍会占用额外内存，不能据此承诺所有模型同时满负载推理。

### 10.2 调度规则

1. 内容分片是无模型的只读生产者；模型执行分两条车道：轻车道串行调度 ASR、Aligner、Embedding（小模型），重车道独立串行调度 Qwen3.8 描述；同一模型车道内一次只有一个满负载推理。
2. 两条车道可以同时各持有一个推理；ASR/对齐/Embedding 的短突发与 Qwen3.8 的长任务在 GPU 上分时共存。若实测争抢明显（描述延迟方差增大或 Metal 工作集超限），退挡为粗粒度交替。
3. AVFoundation 解码、磁盘/网络读取和有限的 Vision OCR 可以与模型任务重叠。
4. 同一音频块必须先 ASR 再 Align，二者存在数据依赖，不能并行。
5. Worker 生命周期归模型运行时而非建库车道所有。Aligner、Embedding 与查询共享同一运行时，建库到达队尾不会卸载查询 Worker；只有模型配置切换、显式运行时停止或应用退出才释放。
6. 前台查询在轻车道资源的等待队列中优先于尚未开始的后台调用，但不抢占正在运行的原子调用，也不暂停任何后台车道。
7. 不通过增加模型进程数量来追求并发；所有并发上限由实机基准决定。
8. Aligner 与 Embedding 在 oMLX 中保持卸载；Worker 处理期间可以同时持有这两个不同职责的权重，但不并行推理，也不创建第二个 Worker。
9. 若素材来自局域网 NAS，分片生产者仍按视频稳定顺序串行分析；每个完成的视频立即释放给两条模型车道，不形成全库屏障。证据车道在模型计算的同时预读自己的下一个片段，网络读取与 Metal 计算重叠，预读深度为一个片段。

运行模式：

```text
索引态：内容分片按视频生产；轻车道 ASR → Align → OCR → Embedding 串行，
        重车道 Qwen3.8 描述串行，三阶段流水、互不设置全库屏障
交互态：轻车道查询 Embedding 在队列中优先，已经运行的后台调用不中断
```

## 11. 安全、恢复与失效

- 每个任务必须幂等；未变化素材重复扫描不得重复计算。
- 每次认领返回不可转借的尝试令牌；派生提交、失败和取消回队都必须同时匹配运行态与尝试号。
- 派生提交前再次检查素材指纹和输入修订；素材或证据变化时丢弃过期结果。
- 写入采用临时批次加数据库事务，不能出现半套 ASR 或半套索引。
- 应用崩溃后从任务检查点恢复，不清空已完成结果。
- 磁盘不足、无音轨、损坏媒体、模型加载失败、输出格式错误和内存压力都有明确错误状态。
- 单个素材失败不阻塞其他素材，也不自动启动备用模型。
- 模型输出不得覆盖观测事实；描述与推断必须保留来源和版本；
- 用户可移除整个根（目录或文件）或单个视频：移除只删除记录与派生数据，绝不触碰源文件；移除根走级联删除，移除单视频保留排除标记；
- 任意范围可手动重跑（整视频、单片段证据链、单片段描述）：重跑只是把已结束任务重置为待处理，复用同一条流水线，不存在第二条重算路径。

## 12. 正式验收标准

功能第一版已经用单个真实视频跑通；是否达到个人视频库稳定可用，仍需用 20–50 个真实视频建立正式验收集。候选比较只发生在受控验收中，最终只保留胜出的生产实现。

### 12.1 ASR 与时间戳

- 至少 30 条普通话、噪声、方言、多人、音乐背景和外语片段；
- 记录 CER/WER、关键词可检索率和时间戳误差；
- 11 种对齐语言抽样人工标注句首和句尾；
- 验证跨块边界无重复词、缺词和全局时间漂移；
- 记录实时率、峰值内存和长视频连续运行稳定性。

### 12.2 OCR

- 覆盖字幕、招牌、屏幕、斜拍、低光和多语言文字；
- 验证框、置信度、时间和跨帧去重；
- 相同字幕连续出现时不能产生大量重复证据。

### 12.3 语义检索

- 建立至少 50 条带目标片段的真实查询；
- 包含台词查询、场景查询、动作查询、OCR 查询和困难负例；
- 目标片段 Recall@10 达到 90% 才锁定片段长度、抽帧参数和 2B 模型；
- 若比较 8B，只以自有查询的增益和实测吞吐决定是否整体替换；
- 热查询延迟目标：p95 小于 1 秒。

### 12.4 Qwen3.8 描述

- 至少 20 个包含动作、镜头变化、多人、字幕和外语的片段；
- 验证多图顺序正确、结构化输出稳定、无核心事实臆造；
- 记录首次加载时间、单片段耗时和峰值 Metal 工作集；
- 连续运行不得触发 OOM、持续 swap 或不可恢复的 Metal 错误。

### 12.5 数据安全与恢复

- 处理前后抽样校验源文件未变化；
- 未变化文件二次扫描不重算；
- 源文件变化后旧结果不再可见；
- 任意阶段中断后可恢复，且数据库中无半提交结果；
- 用户撤销目录授权后，应用不再读取对应素材。

## 14. 决策记录

### D-001：不设置运行时模型 fallback

- 决策：每项职责只有一个生产实现。
- 理由：避免重复权重、双索引、不可解释分支和维护成本。
- 后果：模型失败会形成明确任务错误，不会自动换模型掩盖问题。

### D-002：使用专用模型链，不使用单一全模态模型

- 决策：ASR、对齐、OCR、Embedding、描述分别使用最适合其输出约束的能力。
- 理由：精确时间戳和检索向量不是全模态生成模型的可靠输出。
- 后果：存在多个非冗余 checkpoint，但只有一条有向处理链。

### D-003：描述只作为增量画面召回，不回灌向量

- 决策：Embedding 直接编码关键帧、ASR 和 OCR；描述生成后把 `summary` 与 `visible_details` 增量写入 FTS，并明确标为画面来源；`uncertainty` 排除，描述不回灌向量。
- 理由：直接帧向量保证描述缺失不会造成基础召回盲区；描述文本可以补充模型识别出的物体、场景和动作，并提供可读的画面命中原因。
- 后果：描述缺失或失败不影响 ASR/OCR/向量检索；已有缓存升级时原地补索引，不重新调用模型。描述是模型派生证据，界面不得冒充原始观测。
- 修订（2026-08-24）：推翻此前“描述仅展示、不参与检索”的约束，保留“不回灌向量、不阻塞检索”的边界。

### D-004：第一版使用 2B Embedding

- 决策：默认 `Qwen3-VL-Embedding-2B`，不同时维护 8B。
- 理由：大量长视频下，2B 的吞吐、内存和索引体积更适合本机处理。
- 后果：8B 只允许在一次性验收中作为替换候选。

### D-005：第一版使用关键帧混合输入

- 决策：Embedding 与描述复用有序关键帧，不依赖整段视频处理器。
- 理由：Mac 原生视频模型路径尚新；共享帧输入更稳定、可审计且减少重复解码。
- 后果：必须在验收集中覆盖动作和短暂视觉事件，确认抽帧不会造成不可接受的召回损失。

### D-006：模型执行分轻/重两条串行车道

- 决策：小模型（ASR/对齐/Embedding）一条串行车道，Qwen3.8 描述另一条串行车道，两车道并行；解码、I/O 和有限 OCR 继续与模型任务重叠。
- 理由：描述是全链路最慢环节；两条车道并行可以让最慢模型持续满载，其余环节为其供料，同时保持每条车道内部严格串行、可审计、可恢复。
- 后果：两个 Metal 客户端分时共存；若实测争抢明显，退挡为粗粒度交替（见 10.2）。

### D-011：描述在建库后自动批量生成（2026-08-18）

- 决策：片段证据与向量提交后自动进入描述队列，由描述车道逐段调用 Qwen3.8；查看界面只读缓存或展示队列状态，不再提供手动生成入口。
- 理由：个人使用以“浏览即有理解结果”为目标；27B 吞吐由独立车道承担，不拖慢检索可用性（向量提交即可搜索）。
- 后果：推翻 0.5 版“只按需生成”的时机约束；描述完成后独立增量补入画面召回，但描述与证据车道仍独立推进、不互相等待，也不再共享视频处理门（见 D-003、D-015）。

### D-015：App、检索、扫描与后台派生按生命周期解耦（2026-08-24）

- 决策：App 浏览只读本地快照；全文检索在数据库打开后先返回，语义检索作为异步、可失败的增强；扫描、证据建库和描述各自拥有任务、状态、失败与恢复边界。任一链路不得取消、重置或停止其他链路。第一版明确采用单窗口，避免把窗口交互状态误当成全局后台状态。
- 理由：这些链路没有业务上的原子依赖。真正需要共享的只有 SQLite 与模型资源，应在资源层短暂排队，而不是用全局暂停或 `processing_gate` 传播生命周期。
- 后果：在线 reconcile 只补队和失效旧产物，启动恢复单独处理崩溃遗留的 `running`；应用进程先取得全生命周期单实例锁，恢复和孤儿临时文件清理才会执行。所有任务变更使用尝试令牌 CAS，描述失效以证据派生 revision 而非墙上时钟判断，全库刷新只重排真正过期的描述。升级前缺少 revision 的描述用旧版已有的“同源指纹且描述提交不早于当前证据”不变量一次性关联到当前 revision，并原地恢复完成任务；无法证明当前的旧描述仍重新排队。扫描只有在完整稳定时才确认缺失。SQLite 在资源层仲裁 writer、App reader 与 search reader，三者不共享 actor 队列，且两个只读连接由 SQLite 拒绝写入。模型配置保存属于显式控制面变更，可建立版本切换屏障，但旧查询自行结束且不得延长后台暂停；普通浏览、搜索、扫描、增删和重跑不借此互相取消。

### D-016：内容感知变长分片与活动代际切换（2026-08-25）

- 决策：20 秒片段不再进入新建库链路。先从源时间轴提取画面变化和静音结束，再由确定性规划器生成 4–30 秒变长片段；边界观察、提取参数和规划器阈值完整持久化，并由完整参数哈希绑定算法版本。旧活动代际持续服务搜索，新代际全部完成向量后原子切换；旧画面描述在新描述补齐前继续提供字面召回。
- 理由：固定时间与内容边界无关，会切断动作、句子或场景；仅用编码 I 帧同样不代表语义。画面变化与停顿是可观测、可复现且无需先调用大模型的第一层信号。
- 后果：多视频形成“分片生产者 → 证据车道 → 描述车道”的流水线，没有全库屏障；数据库保留当前与上一活动代际，从未活动的旧 staged 代际会被取消并删除，物理代表帧随代际切换清扫。画面分析按最多 7,200 个样本自适应采样并以 240 个请求分批，内存和请求数有硬边界；当前生产边界尚未使用 ASR 句末与 OCR 变化，它们只作为规划器已支持的后续证据源，真实长 GOP/NAS 吞吐和多音轨选择仍需验收。

### D-007：模型供应商中立，按能力契约拆分调用路径（2026-08-26 修订）

- 决策：ASR 与描述使用 OpenAI 兼容接口；Aligner 与 Embedding 使用 Media Memory 最小 HTTP 契约或内置 Worker。每项能力分别配置 URL、模型和 key，不根据供应商名称分支。
- 理由：转写与多模态聊天已有可复用协议；强制对齐和多帧融合向量没有等价的通用协议。按能力公开输入输出，比引入 Provider 品牌抽象更小且可验证。
- 后果：本地和远程服务在实现同一契约时可互换；默认仍优先本机，远程配置会产生明确的数据出口。更改 URL、协议或模型会触发对应派生数据重建。

### D-008：只持久化句级时间戳

- 决策：第一版保存一句话的开始和结束时间，不建立逐字时间表。
- 理由：搜索、证据展示和原视频跳转只需要句级定位，逐字存储会增加数据量和复杂度而没有当前产品收益。
- 后果：ForcedAligner 的词/字对齐项只作为句级聚合的临时中间结果，聚合完成后释放。

### D-009：公开发行采用可复现的未公证 DMG（2026-08-26 修订）

- 决策：发布 arm64 DMG、SHA-256 和可选 Homebrew Tap Cask；使用临时签名，不购买 Apple Developer Program，不做 Developer ID 签名、公证、App Store 或自动更新。
- 理由：个人开源项目可以用 GitHub Release 提供可验证的构建；用户已接受首次启动时在“隐私与安全”手动放行。
- 后果：发布流程必须验证 App 签名、DMG 内容与校验和，并清楚写明 Gatekeeper 步骤；若未来要消除系统警告，再单独引入 Developer ID 与公证。

### D-010：个人版先使用唯一精确向量索引

- 决策：SQLite 持久化当前片段向量，搜索进程按版本构建一份内存矩阵，并用 Accelerate 做精确余弦排序。
- 理由：仓库的 10,000 个 2048 维向量性能测试用于在目标硬件验证余量；在当前产品规模引入 ANN 会额外增加持久化、增量更新和一致性成本。
- 后果：时间和内存随片段数线性增长；真实库一旦使热查询 p95 超过 1 秒，就整体替换该唯一实现，不并存备用索引。

## 15. 当前已知限制

1. 11 种语言以外暂不承诺精确句首句尾，只提供 ASR 句段或处理块级定位。
2. 当前内容分片只使用画面变化与静音结束，关键帧输入仍可能遗漏极短动作；ASR 句末与 OCR 变化尚未接入生产边界，必须由真实检索集验证。
3. ASR、检索和 Qwen3.8 描述只在少量真实素材上通过，尚未完成第 12 节的多样本准确率、Recall 与长期稳定性验收。
4. 10,000 向量基准只验证排序核心，不代表含查询 Embedding、数据库取证和 UI 的全库 p95。
5. 四个模型已下载并成功调用，但来源 revision/SHA、转换参数和精确运行时版本尚未全部锁入派生记录。
6. 远程模型服务的数据保留、日志、训练用途和访问控制由服务提供方决定，应用无法替用户验证；配置前必须自行确认。
7. 内置 Worker 仍依赖用户提供的 Python/MLX 环境和模型目录；升级这些运行时后必须先运行真实模型测试。
8. DMG 未做 Developer ID 签名或公证，首次启动会遇到 Gatekeeper 提示，需要用户在系统设置中手动放行。
